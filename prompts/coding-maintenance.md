# 可复用的 Codex 维护提示

以下提示在本轮整理，不冒充历史对话原文。

## 排查真实模型失败

先读 AGENTS.md、失败输入和真实 Trace。对照最终 citations 与本轮 read_doc_span 原文，
确定问题发生在检索、工具、出处、语义、范围、API 还是预算层。不要只看 status。
先用现有记录验证原因，再做最小修复，增加修复前会失败的回归测试。
Live 的下一步仍须由模型选择，不得按文档 ID、题目关键词或预期状态硬编码答案。
保留失败文件，用新报告路径复验。报告实际命令、结果与没有验证的部分。

## 优化 Prompt

读取各版本和对应真实输出，选一个具体错误行为，提出最小调整，同时指出可能增加的
过度拒答和调用成本。使用 --prompt-file 和 --no-final-review 区分 Prompt 与运行时复核效果。
尽量固定问题、模型和资料，记录 Prompt 哈希、语料哈希、response_id、用量与耗时。
小样本结果不能代表普遍准确率。只记录可观察动作，不输出模型内部思考。

## 整理交付记录

对照 git diff、pytest XML、评测 JSON 和 Trace 核对文档。区分出处真实与语义受支持。
采用自然的开发日志口吻，记录具体问题、尝试、失败、取舍与结果，不写模板化宣传。
候选人的手工贡献、本人判断和实际投入如果未确认就保留待确认，不能将 AI 执行写成真人手工完成。
